# Lessons learned — read · use · record

## Duties (every project turn)

1. **Read** documented lessons before acting.
2. **Use** what you read. Do not contradict them without an explicit environment change.
3. **Record** new durable learnings as work proceeds. Do not wait for session end.

Failure is OK. Not learning from failure is not. Record what was tried, why it failed, and what to do instead.

## Before tools or edits

1. Classify the topic.
2. Open the intent router / hub for that topic if you have one.
3. Read the project `LESSONS_LEARNED.md` or `RUN_STEPS` lessons section.
4. Only then run queries, searches, or file edits.

## Record when

- A fix or method is confirmed
- An approach fails
- You discover a reusable pitfall, table rule, or tool command
- Web research yields durable knowledge (store summary + URL)

## Where to write

| Scope | Primary file |
|-------|--------------|
| Active project | `LESSONS_LEARNED.md` or `RUN_STEPS` § Lessons |
| Cross-project policy | Shared rules / knowledge docs |
| One-line routing | Point from the hub to the detailed lesson |

## Forbidden

- Finishing with new knowledge only in chat
- Ending after failure without a lesson row
- Waiting for someone to say “update the docs” when a lesson already applies
